Flow 04 · human authority

Approve → request dispatch → inspect receipts

Approval and sending are separate decisions. Practise approval on the local plan. Attempt dispatch only on a current-window Compose plan with an eligible activity, working C2 worker and Yamcs connection.

  1. Review exact revision
  2. Approve in UI
  3. Send eligible activity
  4. Read receipts

Codex · guide

Be my Constellation OS authority-and-dispatch demo copilot. Read the current C2 evidence sequence and UI/API contracts. Use read-only inspection; I will make every approval and send decision in the UI.

First identify the exact proposed plan version/hash, pending authoring diff, review cursor, net value and stability summary. Guide me through Review and approve as tenant admin; wait for my click and verify the approval receipt. State clearly that this did not contact C2.

Then check whether this environment has an eligible current-window activity, an operating C2 worker and Yamcs. The local dev_api fixture is not sufficient. If any prerequisite is absent, stop at approval and say exactly why. If all are present, show me the activity ID, destination and eligibility. I will use Send selected activity → Request dispatch. After my click, inspect the dispatch request, worker/Yamcs command receipts and Execution observations in order. Distinguish requested, queued, uplinked, executed, failed and unknown states by actual receipts. Never call a request receipt proof of execution. Hand Claude Code the IDs and evidence.

Claude Code · check

Independently verify my Constellation OS authority demo using the plan, approval, activity, dispatch and receipt IDs I paste. Read-only only.
